What this means for tonight's tracker state: `post-tracker.mjs`'s own idempotency rule (see its source comment) always refreshes `claude_update`/`next_action` on every call, so this brief's final write-back (done after this file, per the Deliver-order rule) overwrites those two fields with the findings in this document — the ones that actually matter for what a reader sees on the feature card. However, the **one-per-night** `feature_messages` (the assistant chat message with the starter prompt) and `activity` rows were already posted by the rogue sub-task earlier tonight and are **not** replaced by this run's own write-back call (the script skips re-posting a message/activity row for a feature that already has one tonight). So: tonight's feature cards and next-actions in the Development Manager will match this brief; tonight's chat-thread messages and activity-feed lines for each feature may still carry the sub-task's own (independently-derived, largely but not necessarily identically-worded) phrasing rather than this brief's. The team should know the two can differ slightly tonight, for the reason above — not because two genuinely different audits ran.

Working-tree fallout: the sub-task's local commit `aeb84a8` sat directly on `develop`'s tip rather than on the real `claude/nightly-audit` ancestry (`2026-10-15` → `-16` → `-17` → `-18`'s commits).
