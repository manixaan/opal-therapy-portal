**The one integration failure**: `tests/integration/readonly-and-hardening.itest.js`,
test `D-6/D-7: storage failure behaviour (local backend)`. It simulates an
unwritable storage directory with `fs.chmodSync(dir, 0o000)` and expects
the next write to fail with 5xx. This container runs as `root`
(`id` → `uid=0(root)`), and Linux's standard permission checks don't apply
to root, so the simulated failure never actually occurs and the write
succeeds (201 instead of the expected ≥500). This audit inspected the test
and confirmed the mechanism (root bypasses `chmod`) directly, not just
asserted it — and a prior audit night (2026-09-20) made and recorded the
identical finding, including a suggested fix (mock `fs.writeFile` to
reject for this one case, or skip with a clear message when
`process.getuid?.() === 0`). Still not fixed as of tonight; this remains
report-only territory (`backend/tests/**` edits aren't in scope for a
nightly audit unless a session is specifically asked to fix it).
